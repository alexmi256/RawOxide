# Testing

## Pyramid

| layer | tool | what it covers |
|---|---|---|
| unit | `cargo test` / nextest | framing, codec, tag encoding, sizing, split |
| property | `proptest` | round-trips, capacity invariants, malformed input |
| snapshot | `insta` | JSON sidecar, CLI output, error messages |
| golden | committed fixtures | Python ↔ Rust cross-decode, tag inventory |
| registry | embedded assets | all 307 profiles parse; pools/levels match Python |
| consumer | external tools | `tiffdump`, `exiv2`, `rawpy` acceptance |
| fuzz | `cargo-fuzz` | TIFF/IFD/framing parsers |
| performance | `criterion` | codec, cover, tile compression |
| mutation | `cargo-mutants` | test quality in critical modules |

## Commands

```bash
just test          # cargo nextest run --workspace --all-features
just test-doc      # cargo test --workspace --doc --all-features
just lint          # clippy -D warnings
just coverage      # cargo llvm-cov nextest --lcov --output-path lcov.info
just coverage-html # target/llvm-cov/html/index.html
just bench         # criterion
just mutants       # cargo-mutants (slow)
just ci            # fmt-check + lint + check + test + doc-test + deny + audit + doc
```

For peak-RSS comparisons against Python, use GNU time:

```bash
/usr/bin/time -v cargo run -p rawhide-cli -- capacity --width 2048 --height 1536
```

Optional local acceleration: `RUSTC_WRAPPER=sccache` for compilation caching and
`RUSTFLAGS='-C link-arg=-fuse-ld=mold'` for faster linking. Keep both out of the
committed Cargo config so contributors do not need them.

Coverage requires `cargo-llvm-cov` and LLVM tools. With rustup:

```bash
rustup component add llvm-tools-preview
cargo install --locked cargo-llvm-cov
```

With the distro toolchain, point cargo-llvm-cov at the system LLVM if needed:

```bash
LLVM_COV=/usr/bin/llvm-cov LLVM_PROFDATA=/usr/bin/llvm-profdata just coverage
```

## Golden fixtures

Fixtures live in `fixtures/` and are generated by the Python reference:

```bash
just fixtures
# or: python3 scripts/gen_fixtures.py --force
```

The script writes:

- `fixtures/payloads/*.bin` — deterministic payloads;
- `fixtures/dng/*.dng` — small DNGs covering linear/cfa, 8/10/14/16-bit,
  planes, frames, keyed, Deflate and split;
- `fixtures/golden/*.json` — framing/capacity/format vectors;
- `fixtures/manifest.json` — sizes, SHA-256, generation command and Python
  version/commit.

Static assets are regenerated from the Python checkout:

```bash
python3 scripts/embed_profiles.py   # 307 profile JSON + Adobe blobs
python3 scripts/embed_geo.py        # zones.bin tz/land table
```

Fixtures are committed so Rust tests are hermetic. `--force` is required to
overwrite them; review the diff like source. Never edit a DNG by hand.

The Python project's `.gitignore` ignores `*.dng`; the Rust `fixtures/`
directory is outside that project and is tracked explicitly.

### Reproducibility note

The Python oracle currently anchors `date_window_days` to `datetime.now()`
(`stegodng/fidelity.py`), which makes seeded metadata for fidelity profiles
non-reproducible across seconds. Fixture generation uses the default `gfx_100`
profile (no fidelity date window) and explicit `--image-time` where needed.
Fix the Python bug before adding metadata snapshots that depend on a date
window.

### Profile/metadata checks

```bash
cargo run -p rawhide-cli -- encode \
  -i fixtures/payloads/payload_3000.bin -o /tmp/canon.dng \
  --camera-profile canon_eos_80d --width 128 --height 96 --seed 12

exiv2 -pa /tmp/canon.dng | grep -E \
  "Make|Model|ExposureTime|FNumber|ISOSpeedRatings|DateTimeOriginal|LensModel|BodySerialNumber|AsShotNeutral|BaselineExposure"
```

The camera make/model/lens pools, serial prefixes and calibration matrices must
match the embedded `assets/profiles/<slug>/profile.json`; `--image-time` must
appear verbatim in `DateTimeOriginal` and `DateTime`.

## Cross-decode matrix

Run for every depth (8/10/12/14/16), mode (`linear`/`cfa`), planes (1, 2, 4, 8,
16), frames (1, 2, 8), compression (`none`, `adobe_deflate` where legal), key
on/off, single/split, classic/BigTIFF:

1. Python encode → Rust decode → payload identical.
2. Rust encode → Python decode → payload identical.
3. `tiffdump` tag inventory diff (offset-only differences allowed).
4. `exiv2 -pa` EXIF/DNG/XMP diff; skip BigTIFF (exiv2 cannot parse it).
5. `rawpy.imread` + `postprocess` succeeds for both.
6. Rust encode twice with the same seed → identical bytes (offset tags
   excluded).
7. Peak RSS ceiling test at 11 648×8 736 and nightly at 23 296×17 472.

## Writer cross-check

The writer must be readable by the Python reference and a real RAW decoder, not
just the Rust reader:

```bash
cd rust
cargo run -p rawhide-cli -- encode \
  -i fixtures/payloads/payload_3000.bin -o /tmp/spike.dng

# multi-frame (3 SubIFDs) and split set (2 chunks, Python album layout)
cargo run -p rawhide-cli -- encode \
  -i fixtures/payloads/payload_5000.bin -o /tmp/frames.dng --raw-frames 3
cargo run -p rawhide-cli -- encode \
  -i fixtures/payloads/payload_5000.bin -o /tmp/split/vol.dng \
  --split-file 3000 --split-file-metadata-seq PageNumber

cd ../RawHide
.venv/bin/python stego_dng.py decode -i /tmp/spike.dng -o /tmp/spike.bin
cmp /tmp/spike.bin ../rust/fixtures/payloads/payload_3000.bin

# multi-frame uses the normal decode path
.venv/bin/python stego_dng.py decode -i /tmp/frames.dng -o /tmp/frames.bin --no-progress
cmp /tmp/frames.bin ../rust/fixtures/payloads/payload_5000.bin

# split sets need the same sequence field at decode time; PageNumber fails
# closed on a missing or extra chunk, ImageNumber cannot detect either.
.venv/bin/python stego_dng.py decode -i /tmp/split/payload_5000/vol0001.dng \
  /tmp/split/payload_5000/vol0002.dng --split-file-metadata-seq PageNumber \
  -o /tmp/split.bin --no-progress
cmp /tmp/split.bin ../rust/fixtures/payloads/payload_5000.bin

.venv/bin/python - <<'PY'
import rawpy
for path in ("/tmp/spike.dng", "/tmp/frames.dng"):
    with rawpy.imread(path) as raw:
        print(path, raw.sizes)
        raw.postprocess()
PY

tiffdump /tmp/frames.dng | head -80
exiv2 -pa /tmp/frames.dng | head -60
```

`rawpy.postprocess()` succeeding is the strongest gate; `tiffdump`/`exiv2`
confirm the LinearRaw SubIFD, preview and EXIF split-marker inventory. Split
ordering is also tested in Rust by passing chunks in reverse order.

## Consumer checks

```bash
tiffdump out.dng | head -80
exiv2 -pa out.dng | head -80
python3 - <<'PY'
import rawpy
with rawpy.imread("out.dng") as raw:
    print(raw.sizes)
PY
```

## Benchmarks

`just bench` runs criterion with a 1 MiB payload over a 2048×1536×3 `u16`
cover. Record results in `docs/benchmarks.md` when making performance claims.
Use `hyperfine` for end-to-end CLI comparisons against Python.

## Hermeticity

- No network in tests. Thumbnail tests inject an opener.
- No writes outside `tempfile::TempDir`.
- No reliance on wall-clock time; inject/pin `image_time`.
- No test-order dependence; each test owns its directories and seeds.
