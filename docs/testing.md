# Testing

## Pyramid

| layer | tool | what it covers |
|---|---|---|
| unit | `cargo test` / nextest | framing, codec, tag encoding, sizing, split |
| property | `proptest` | round-trips, capacity invariants, malformed input |
| CLI/JSON | `assert_cmd` + `serde_json` | command output, JSON sidecar shape and errors |
| golden | committed fixtures | decode, framing, codec and capacity vectors |
| registry | embedded assets | every profile parses; pools/levels resolve |
| consumer | external tools (manual) | `tiffdump`, `exiv2`, `rawpy` acceptance |
| fuzz | `cargo-fuzz` (planned) | TIFF/IFD/framing parsers |
| performance | `criterion` | codec, cover, tile compression |
| mutation | `cargo-mutants` | test quality in critical modules |

## Commands

```bash
just test          # cargo nextest run --workspace --all-features
just test-doc      # cargo test --workspace --doc --all-features
just lint          # clippy -D warnings
just fmt-check     # rustfmt check
just coverage      # cargo llvm-cov nextest --lcov --output-path lcov.info
just coverage-html # target/llvm-cov/html/index.html
just bench         # criterion
just mutants       # cargo-mutants (slow)
just ci            # fmt-check + lint + check + test + doc-test + deny + audit + doc
```

Coverage requires `cargo-llvm-cov` and LLVM tools. With rustup:

```bash
rustup component add llvm-tools-preview
cargo install --locked cargo-llvm-cov
```

With a distro toolchain, point cargo-llvm-cov at the system LLVM if needed:

```bash
LLVM_COV=/usr/bin/llvm-cov LLVM_PROFDATA=/usr/bin/llvm-profdata just coverage
```

Optional local acceleration: `RUSTC_WRAPPER=sccache` for compilation caching and
`RUSTFLAGS='-C link-arg=-fuse-ld=mold'` for faster linking. Keep both out of the
committed Cargo config so contributors do not need them.

## Golden fixtures

Fixtures live in `fixtures/` and are committed so the suite is hermetic:

- `fixtures/payloads/*.bin` — deterministic payloads;
- `fixtures/dng/*.dng` — small DNGs covering linear/CFA, 8/10/14/16-bit,
  planes, frames, keyed, Deflate and split sets;
- `fixtures/golden/*.json` — framing, codec, capacity and environment vectors;
- `fixtures/manifest.json` — sizes, SHA-256 hashes and generation provenance.

They are generated by the reference implementation and reviewed like source:

```bash
just fixtures
# or: python3 scripts/gen_fixtures.py --force
```

`--force` is required to overwrite existing files. Never edit a DNG or payload
by hand.

Static assets are refreshed from the reference checkout with:

```bash
python3 scripts/embed_profiles.py   # 307 profile JSON + Adobe blobs
python3 scripts/embed_geo.py        # zones.bin tz/land table
```

Both scripts default to a `RawHide/` checkout in the repository root; set
`RAWHIDE_ORACLE` to point elsewhere. Regenerated assets and the generated
profile table are reviewed like ordinary source.

### Reproducibility note

Seeded metadata that depends on a rolling date window is anchored once per
encode run. Fixture generation pins `--image-time` where a snapshot would
otherwise move with the wall clock.

## Profile and metadata checks

```bash
cargo run -p rawoxide-cli -- encode \
  -i fixtures/payloads/payload_3000.bin -o /tmp/canon.dng \
  --camera-profile canon_eos_80d --width 128 --height 96 --seed 12

exiv2 -pa /tmp/canon.dng | grep -E \
  "Make|Model|ExposureTime|FNumber|ISOSpeedRatings|DateTimeOriginal|LensModel|BodySerialNumber|AsShotNeutral|BaselineExposure"
```

The camera make/model/lens pools, serial prefixes and calibration matrices come
from `assets/profiles/<slug>/profile.json`; `--image-time` must appear verbatim
in `DateTimeOriginal` and `DateTime`.

## Writer cross-check

The writer must be readable by a real raw decoder, not only by its own reader:

```bash
cargo run -p rawoxide-cli -- encode \
  -i fixtures/payloads/payload_3000.bin -o /tmp/spike.dng

# multi-frame (3 SubIFDs) and split set (2 chunks, album layout)
cargo run -p rawoxide-cli -- encode \
  -i fixtures/payloads/payload_5000.bin -o /tmp/frames.dng --raw-frames 3
cargo run -p rawoxide-cli -- encode \
  -i fixtures/payloads/payload_5000.bin -o /tmp/split/vol.dng \
  --split-file 3000 --split-file-metadata-seq PageNumber
```

`rawpy.postprocess()` succeeding is the strongest acceptance gate:

```bash
python3 - <<'PY'
import rawpy
for path in ("/tmp/spike.dng", "/tmp/frames.dng"):
    with rawpy.imread(path) as raw:
        print(path, raw.sizes)
        raw.postprocess()
PY

tiffdump /tmp/frames.dng | head -80
exiv2 -pa /tmp/frames.dng | head -60
```

`tiffdump`/`exiv2` confirm the `LinearRaw` SubIFD, preview and EXIF split-marker
inventory. Split ordering is also tested in Rust by passing chunks in reverse
order.

## Cross-decode matrix

When changing the writer, reader or framing, also run the optional
interoperability gate against the reference implementation:

```bash
RAWHIDE_ORACLE=./RawHide just cross-decode
```

It covers linear, CFA, multi-frame and split output in both directions and
compares written tag inventories. Run the full matrix manually for a release:

For every depth (8/10/12/14/16), mode (`linear`/`cfa`), planes (1, 2, 4, 8, 16),
frames (1, 2, 8), compression (`none`, `adobe_deflate` where legal), key on/off,
single/split, classic/BigTIFF:

1. RawOxide encode → reference decode → payload identical.
2. Reference encode → RawOxide decode → payload identical.
3. `tiffdump` tag inventory diff (offset-only differences allowed).
4. `exiv2 -pa` EXIF/DNG/XMP diff; skip BigTIFF (`exiv2` cannot parse it).
5. `rawpy.imread` + `postprocess` succeeds for classic output.
6. RawOxide encode twice with the same seed → identical bytes (offset tags
   excluded).
7. Peak RSS ceiling test at 11 648×8 736 and nightly at 23 296×17 472.

## Consumer checks

These are manual; CI runs the test suite but not `rawpy`/`exiv2`/`tiffdump`.

```bash
tiffdump out.dng | head -80
exiv2 -pa out.dng | head -80
python3 - <<'PY'
import rawpy
with rawpy.imread("out.dng") as raw:
    print(raw.sizes)
PY
```

## Fuzzing (not implemented)

No fuzz targets or corpus are committed yet. When added:

```bash
cargo install --locked cargo-fuzz
cargo fuzz init
cargo fuzz add decode_frame
cargo fuzz add parse_ifd
cargo fuzz run decode_frame -- -max_total_time=60
```

Add a short nightly budget and `fuzz/corpus/` once the parsers are stable.

## Benchmarks

`just bench` runs criterion with a 1 MiB payload over a 2048×1536×3 `u16` cover.
No benchmark result file is committed; record results in `docs/benchmarks.md`
when making performance claims. Use `hyperfine` for end-to-end CLI measurements.

## Hermeticity

- No network in tests. Thumbnail tests inject an opener.
- No writes outside `tempfile::TempDir`.
- No reliance on wall-clock time; inject or pin `image_time`.
- No test-order dependence; each test owns its directories and seeds.
